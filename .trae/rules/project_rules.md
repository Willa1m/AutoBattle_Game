# 游戏项目开发规范

## 1. 项目概述

本规范文档旨在规范游戏项目的开发流程、代码标准和测试方法，确保团队协作效率和代码质量。

## 2. 开发规范

### 2.1 技术栈选择
- 后端语言：根据项目需求选择合适的编程语言
- 前端/交互：使用HTML、CSS、TypeScript等技术实现游戏的前端交互
- 版本控制：使用Git进行代码管理，采用Git Flow工作流

### 2.2 代码规范
- 遵循所选语言的官方代码风格指南
- 所有函数和类必须包含清晰的文档注释
- 变量和函数命名采用有意义的名称，避免缩写
- 代码缩进统一，保持代码结构清晰
- 每个文件长度不超过500行，超过时需拆分

## 3. 测试规范

### 3.1 测试方法
- **禁止使用图形化测试**，所有测试必须通过控制台代码完成
- 编写自动化测试用例，覆盖核心功能
- 测试用例应包含正常情况和边界情况

### 3.2 测试流程
- 新功能开发完成后，开发者需编写对应的测试用例
- 提交代码前必须通过所有相关测试
- 每日构建时运行全量测试

## 4. 项目文件管理

### 4.1 KEYS.md 文件
- 项目启动前必须首先创建KEYS.md文件
- 所有创建的程序文件、函数和API调用必须记录在KEYS.md中
- 每次会话开始前，必须查阅KEYS.md，避免重复创建或无效调用
- 每次创建新文件或API调用后，立即更新KEYS.md

### 4.2 文件组织结构project-root/
├── src/             # 源代码目录
├── tests/           # 测试代码目录
├── docs/            # 文档目录
├── RULE.md          # 本规范文件
└── KEYS.md          # 项目关键信息记录文件
## 5. 协作规范

- 每次开发前更新本地代码，确保基于最新版本开发
- 提交代码时必须填写清晰的提交信息
- 功能开发完成后提交Pull Request进行代码审查
